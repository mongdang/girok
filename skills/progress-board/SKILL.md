# 현황판 갱신 규칙

현황판(`PROGRESS.md`)은 **지금 상태의 스냅샷**이다. 사건의 누적 로그가 아니다.

## 구조

| 절 | 담는 것 |
|---|---|
| 일자별 작업 로그 | 그날 최종적으로 남은 결과 한 줄. 되돌린 시행착오는 적지 않는다 |
| 상태 요약 | 서브시스템별 현재 상태 배지 + (해당되면) 검증 수준 |
| 활성 위험 | 지금 열려 있는 위험. 안전 게이트 항목은 **번호로 인용**하고 내용을 재서술하지 않는다 |
| 열린 질문 | 아직 결정되지 않은 것. 결정되면 ADR 로 옮기고 여기서 지운다 |

일자별 로그는 **맨 위**에 둔다 – 최신이 먼저 보여야 한다.

## 갱신할 때

1. **새 내용을 맨 아래에 이어 붙이기만 하지 않는다.** 매번 문서 전체 구조를 다시 훑어
   "지금 처음 읽어도 깔끔한 상태"로 다듬는다. 이게 이 문서가 낡지 않는 유일한 방법이다.
2. 섹션을 추가·삭제하거나 제목을 바꾸면 그 문서의 `## 목차`도 **같은 편집에서** 고친다.
3. 고친 뒤 검사기를 돌린다 – `python {notesDir}/.method/scripts/check_docs.py`.
   목차 앵커·ADR 인용 무결성·표 연속성·문서 크기를 한 번에 본다.
4. 세션 마무리 시점에 오늘 날짜 행을 추가한다(같은 날짜면 그 행을 고쳐 씀). 같은 시점에
   상태 요약 표도 훑어 바뀐 서브시스템 행을 고친다.

## 인용 규칙

- ADR 은 ID 로만 인용한다 – 결정 내용을 현황판에 옮겨 적지 않는다.
- 다른 저장소의 ADR 을 인용할 땐 `` `저장소명`의 ADR-NNN `` 형태로 쓴다(numbered 스타일이면
  `` `저장소명`의 decisions/NNN ``). 그래야 검사기의 존재 검사에서 제외된다.
- 안전 게이트 항목은 `SAFETY_GATE.md #<번호>` 로 인용한다.

## 표 작성 – 검사기가 잡는 실수

> [!WARNING]
> **표 행 사이에 빈 줄을 넣지 않는다.** GFM 에서 표가 끊겨 이후 행이 표 밖 텍스트로
> 렌더링된다. 반복 재발한 실수라 검사기가 잡는다.

표에 행을 추가할 땐 편집 앵커를 다음 헤더가 아니라 **표의 마지막 행 끝**으로 잡는다 –
헤더를 앵커로 잡으면 그 앞의 빈 줄이 표와 새 행 사이에 남는다.

> [!WARNING]
> **헤더에 공백으로 감싼 구분 문자(` – `, ` · `)를 쓰지 않는다.** 검사기 슬러그와 GitHub
> 실제 앵커가 하이픈 개수에서 갈린다. `:` 처럼 앞 단어에 붙이면 일치한다.

## 크기 한계

설정 `limits` 의 값을 넘으면 경고한다(기본: 규칙 문서 20KB, 현황판 30KB). 넘었으면 새
내용을 줄이는 게 아니라 **완결된 서사를 `docs/archive/` 로 옮긴다.**

## 아카이브 이관

서사를 `docs/archive/` 로 옮길 때, 그 안의 **미해결 확인 항목은 전부 현황판의 열린 질문·
활성 위험 또는 안전 게이트로 승격한 뒤** 동결한다. 동결 문서에만 남은 확인 항목은 영영
갱신되지 않는다 – 실제 누락 사례가 있다.

아카이브는 이동 시점 원문 그대로 둔다. 형식을 고치지도, 내용을 갱신하지도 않는다.

## 병행 작업 중

기록처가 `docs_<id>/PROGRESS.md` 로 바뀌고 문서 스탬프가 추가된다. `parallel-docs` 스킬 참고.
