## 먼저: 나는 어느 쪽인가

할 일이 둘로 갈린다. 대부분은 왼쪽이다.

| | 작업만 한다 | 도입·갱신도 한다 |
|---|---|---|
| 어떤 사람 | 이미 girok 이 들어간 저장소를 받아서 일한다 | 저장소에 girok 을 새로 넣거나, 규칙 개정을 내려받는다 |
| 필요한 것 | Claude Code · git · Python 3.10+ | 왼쪽 + **girok 플러그인** |
| 따라갈 절 | §1 → §2 → §3 → §5 | §1 → §2 → §3 → §4 → §5 |

훅·검사기·규칙 전문은 저장소에 함께 커밋돼 있고(`.method/`), 훅 등록도 저장소의
`.claude/settings.json` 에 있다. 그래서 작업만 할 사람은 플러그인을 깔지 않아도 같은 검사가
돈다.

## 1. 준비물 설치

### 한 줄로 (Windows)

PowerShell 에서:

```powershell
irm https://raw.githubusercontent.com/mongdang/girok/master/install.ps1 | iex
```

git · Python 3.10+ · Claude Code 중 **없는 것만** `winget` 으로 설치하고, 이어서 girok
플러그인까지 설치한다(§4). 이미 있는 것은 건드리지 않는다. 끝나면 **새 터미널을 열고** §3
으로 간다.

> [!NOTE]
> 플러그인을 설치할 때 Python·git 이 같이 깔리게 할 수는 없다. Claude Code 는 플러그인
> 설치 시점에 플러그인의 코드를 실행하지 않고, 마켓플레이스를 받는 것부터가 git 을
> 필요로 한다. 그래서 그 앞 단계를 이 스크립트가 맡는다.

### 하나씩

| | 확인 | 없으면 (Windows) |
|---|---|---|
| Claude Code | `claude --version` | PowerShell 에서 `irm https://claude.ai/install.ps1 \| iex` |
| git | `git --version` | `winget install Git.Git` |
| Python 3.10 이상 | `python --version` | `winget install Python.Python.3.13` 또는 [python.org](https://www.python.org/downloads/) |

macOS·Linux 는 Claude Code 를 `curl -fsSL https://claude.ai/install.sh | bash` 로, git 과
Python 은 패키지 관리자로 설치한다.

> [!IMPORTANT]
> python.org 설치 파일을 쓰면 첫 화면의 **"Add python.exe to PATH"** 를 반드시 체크한다.
> 체크하지 않으면 Python 이 깔려 있어도 훅이 찾지 못한다(§2).
>
> 설치한 뒤에는 **터미널과 Claude Code 를 둘 다 껐다 켠다.** PATH 는 프로세스가 시작할 때
> 읽히므로, 켜져 있던 세션은 새 Python 을 모른다.

Git Bash 는 필요 없다 - 훅 진입점이 bash·cmd.exe·PowerShell 셋 다에서 돈다. pip 로 깔
패키지도 없다 - 훅과 검사기는 표준 라이브러리만 쓴다.

## 2. Python - 어느 것이 쓰이나

**PATH 에 잡히는 Python 만 쓰인다.** Claude Code 는 자체 Python 을 들고 있지 않고, girok 도
Python 을 설치하거나 찾아다니지 않는다. 훅 래퍼(`run-hook.cmd`)가 아래 순서로 직접 실행해
보고, 3.10 이상으로 확인된 첫 번째 것을 쓴다.

| | 시도 순서 |
|---|---|
| Windows | `python` → `py -3` |
| macOS·Linux | `python3` → `python` → `py` |

### 그래서 "Claude 가 깔아 준 Python" 은?

경우에 따라 다르다. 어디에 깔렸느냐가 아니라 **PATH 에 올라갔느냐**로 정해진다.

| 그 Python 이 깔린 방식 | 훅이 쓰나 |
|---|---|
| python.org 설치 파일 · `winget` - PATH 등록됨 | 쓴다 |
| `py` 런처에 등록됨 (`py -0p` 에 보임) | 쓴다 - `python` 이 없거나 탈락했을 때 |
| `uv` 가 받아 둔 것 (`uv python list` 에만 보임) | **안 쓴다** - uv 전용 폴더에 있고 PATH 에 없다 |
| 가상환경(venv)·conda 환경 안의 것 | 그 환경을 활성화한 터미널에서 `claude` 를 켰을 때만 |
| Microsoft Store 바로가기 (`python3` 가 아무것도 안 하고 끝남) | 안 쓴다 - 인터프리터가 아니라서 래퍼가 걸러낸다 |

MCP 서버나 도구를 설치하다가 `uv` 가 Python 을 받아 두는 경우가 흔하다. 그 Python 은 `uvx`
로 띄우는 도구만 쓰고, girok 훅과는 무관하다. **새 PC 에 uv 의 Python 만 있다면 훅은 돌지
않는다** - §1 대로 Python 을 따로 설치할 것.

### 지금 어느 것이 잡히는지 확인

```bash
python -c "import sys; print(sys.version); print(sys.executable)"
```

버전이 3.10 이상이고 경로가 찍히면 그것이 훅이 쓰는 Python 이다. 명령을 못 찾는다고 나오면
Windows 에서는 `py -0p` 도 확인한다 - 둘 다 비어 있으면 쓸 수 있는 Python 이 없는 것이다.

> [!WARNING]
> Python 을 못 찾으면 훅은 조용히 넘어가지 않고 stderr 에
> `[girok] No usable Python 3.10+: hooks are NOT running` 을 남긴다. 그 상태에서는 **검사가
> 하나도 돌지 않고**, 세션 시작 블록이 뜨지 않아 `CLAUDE.md` 게이트가 작업을 멈춘다.

## 3. 저장소 받고 켜기

```bash
git clone <저장소 주소>
cd <저장소 폴더>
claude
```

처음 켜면 **"이 폴더를 신뢰하겠느냐"** 고 묻는다. **예** 를 누른다. 신뢰하기 전에는 저장소에
커밋된 `.claude/settings.json` 이 무시돼서 훅이 걸리지 않는다.

커밋에 쓸 git 사용자 정보도 이때 맞춰 둔다. 병행 모드 저장소는 `git user.email` 로 작업자를
판별한다.

```bash
git config --global user.name "<이름>"
git config --global user.email "<이메일>"
```

이메일이 `.claude/girok.json` 의 `workers` 에 없으면 세션이 누구인지 묻는다 - 자세한 것은
[사용법 §2](%EC%82%AC%EC%9A%A9%EB%B2%95.md#workers-는-채워야-진행된다).

## 4. 플러그인 설치 - 도입·갱신을 할 사람만

작업만 할 거라면 건너뛴다. 터미널에서(Claude 밖에서):

```bash
claude plugin marketplace add mongdang/girok
claude plugin install girok@mongdang
```

Claude Code 안에서라면 `/plugin marketplace add mongdang/girok` → `/plugin install girok@mongdang`.
설치 후 **Claude Code 를 껐다 켠다.**

이 PC 에서 저장소에 girok 을 처음 넣는다면, 저장소 폴더에서 Claude 를 켜고 `/notes` 를
돌린다 - [사용법 §2](%EC%82%AC%EC%9A%A9%EB%B2%95.md#2-저장소에-처음-도입할-때).

`/notes` 는 맨 먼저 Python 을 확인한다. 쓸 수 있는 3.10+ 가 없으면 설치할지 묻고, 승인하면
직접 설치한다(Windows `winget`, macOS `brew`). 그 경우 §1 의 Python 설치는 건너뛰어도
되지만, 끝난 뒤 **Claude Code 를 껐다 켜야** 훅이 새 Python 을 찾는다.

나중에 규칙 개정을 받을 때:

```bash
claude plugin marketplace update mongdang
claude plugin update girok@mongdang
```

## 5. 설치 확인

저장소 폴더에서 Claude 를 켜고 이렇게 묻는다:

```
지금 이 저장소 현황 알려줘
```

판본(`ready vX.Y.Z`)·작업자·현황판·안전 게이트 상태를 답하면 된 것이다. 각 줄의 뜻은
[사용법 §4](%EC%82%AC%EC%9A%A9%EB%B2%95.md#4-세션-첫-화면에-뭐가-뜨나).

| 확인할 것 | 통과 기준 |
|---|---|
| Python | §2 의 확인 명령이 3.10 이상과 경로를 찍는다 |
| 폴더 신뢰 | Claude 를 다시 켰을 때 신뢰 프롬프트가 또 뜨지 않는다 |
| 훅 | 위 질문에 `ready` 판본과 현황판 경로가 나온다 |
| 플러그인 (§4 를 한 경우) | `/notes` 가 명령으로 잡힌다 |

## 6. 안 될 때

| 증상 | 먼저 볼 것 |
|---|---|
| 아무것도 모르는 것처럼 답한다 / `ready` 가 없다 | 폴더 신뢰(§3) → Python(§2) → Claude 를 완전히 껐다 켠다 |
| `No usable Python 3.10+` 가 뜬다 | §2 - PATH 에 Python 이 없다. 설치 후 터미널까지 다시 켠다 |
| Python 을 깔았는데도 못 찾는다 | "Add python.exe to PATH" 를 빼먹었거나, 설치 전에 켜 둔 터미널이다 |
| `hook ... timed out` 이 뜬다 | PC 의 프로세스 생성이 느린 경우다 - [사용법 §7](%EC%82%AC%EC%9A%A9%EB%B2%95.md#7-문제-해결) |
| `/notes` 가 없다고 나온다 | 플러그인 미설치(§4) 이거나 설치 후 Claude 를 다시 켜지 않았다 |

그 밖의 증상은 [사용법 §7 문제 해결](%EC%82%AC%EC%9A%A9%EB%B2%95.md#7-문제-해결) 에 있다.
