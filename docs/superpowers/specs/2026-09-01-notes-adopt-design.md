## 배경

`/notes` 초기화는 뼈대만 만든다. `notes_survey.py` 가 기존 관례를 읽어 설정을
제안하는 데까지는 가지만, **이미 있던 문서를 새 자리로 옮기는 일은 아무도 하지
않는다.** 사람이 손으로 하거나, 안 하고 방치된다.

`eq-agent-v3` 가 그 상태다. girok 이 들어가 있고(`.claude/girok.json`), survey 가
"파일을 옮기지 말고 설정을 저장소에 맞춰라"로 판단해 `notesDir: "."`,
`board: "STATE.md"`, `adrStyle: "numbered"` 로 흡수했다. 파일은 하나도 안 움직였다.

이 설계는 그 반대 방향을 추가한다 — **저장소를 girok 표준 레이아웃에 맞춘다.**

| | 현행 (survey) | 추가 (adopt) |
|---|---|---|
| 맞추는 쪽 | 설정을 저장소에 | 저장소를 girok 표준에 |
| 파일 이동 | 없음 | 있음 |
| 주된 위험 | 저장소마다 레이아웃이 제각각 | 문서 간 링크가 깨진다 |

두 방향은 배타적이지 않다. survey 는 계속 남고, adopt 는 사람이 부를 때 돈다.

## 목표와 비목표

목표는 셋이다.

1. 기존 기록을 **하나도 잃지 않고** girok 체계로 옮긴다.
2. 무엇을 어디로 옮길지의 **판단은 사람과 모델이**, **이동은 스크립트가** 한다.
3. 손이 많이 가는 곳(git 정비, `.gitignore`, 파일명 정규화, 링크 재작성)은
   **끝까지 자동으로** 처리한다. 사람에게 되묻지 않는다.

비목표는 셋이다.

- **마크다운 문서만 다룬다.** 코드·데이터(`*.jsonl`, 계약·스키마 `*.json`, 소스
  디렉토리)는 손대지 않는다. 코드가 경로로 읽고 있을 수 있어 옮기면 프로그램이 깨진다.
- 문서 **내용을 고치거나 다듬지 않는다.** 병합은 이어붙이기까지다.
- 저장소 밖에 있는 기록의 반입은 이번 범위가 아니다.

## 전체 흐름

```
notes_adopt.py backup            ← 어떤 쓰기보다 먼저. 손대기 전 원본 그대로
notes_adopt.py plan              ← 읽기 전용. .claude/girok-adopt.json 을 쓴다
      ↓ 모델이 role "?" 를 전부 읽고 채운다 (목적지 + 병합 여부까지)
      ↓ 사람은 결과 표만 확인한다
notes_adopt.py apply --confirm <저장소명>
      git 정비 → 첫 커밋 → 태그 → git mv → 병합 → 링크 재작성 → girok.json 갱신
notes_adopt.py verify            ← SHA-1 대조 · 병합 원문 줄 검사 · 깨진 링크
```

## 0단계 백업

girok 이 이 저장소에 **처음 쓰기를 하기 직전 단 한 번** 돈다. `git init` 보다도,
`notes_init` 의 뼈대 생성보다도 먼저다. 그래야 백업이 "girok 이 손대기 전 원본"이 된다.

| 항목 | 결정 |
|---|---|
| 범위 | 저장소 폴더 **전체**. `.git`·`node_modules`·빌드 산출물까지 제외 없이 |
| 위치 | 저장소 바로 바깥의 `<저장소명>-girok-backup-<YYYYMMDD>/` |
| 검증 | 복사 후 **파일 개수 + 총 바이트 대조** |
| 실패 시 | **이후 전 단계 중단.** 백업이 안 됐으면 아무것도 안 움직인다 |
| 재실행 | 백업 표식이 있으면 건너뛴다 |

제외 목록을 두지 않는 이유: 제외한 항목이 나중에 필요했던 경우를 되돌릴 방법이 없다.
디스크는 싸다. (실측: `eq-agent-v3` 전체 4.6MB · 783개 파일)

git 이 이미 있으면 `girok-adopt-before-<YYYYMMDD>` 태그도 함께 찍는다.
**태그는 `git push` 로 안 나간다 — `--tags` 를 따로 줘야 한다.** 안 그러면 백업의
절반이 이 머신에만 남는다.

## 1단계 git 정비

git 이 없으면 중단하지 않고 **정비를 이식의 일부로 수행한다.**

| 발견 | 해결 | 기록 |
|---|---|---|
| `.git` 없음 | `git init` | `gitSetup.init: true` |
| `node_modules/` `__pycache__` `build/` `dist/` `*.pyc` | `.gitignore` 추가 | 항목별 |
| `.env` `*.key` `*.pem` `credentials*` | `.gitignore` 추가 | **"비밀로 판단해 제외함"** |
| 10MB 초과 파일 | `.gitignore` 추가 | **"git 밖에 남는다 = 백업 폴더에만 있다"** |
| `.gitignore` 이미 있음 | 존중, 없는 항목만 덧붙임 | 추가한 줄에 `# girok:adopt <날짜>` |

기록은 세 군데에 남긴다 — `.claude/girok-adopt.json` 의 `gitSetup` 절(기계용),
`.gitignore` 주석(현장용), 이식 후 현황판 한 줄(사람용).

### 원격이 없을 때

`git init` 한 저장소엔 `remote` 가 없다. 원격 주소는 사람만 아는 값이라 만들 수 없다.
**멈추지 않고 끝까지 진행**하고, 마지막에 남긴다.

> 원격이 없어 push 를 못 했다. `git remote add origin <주소>` 후
> `git push -u origin <브랜치> --tags` 하면 밀린 커밋과 백업 태그가 함께 올라간다.

## 2단계 루트 판정

`git init` 을 자동으로 하는 이상, **"여기가 프로젝트 루트가 맞나"** 를 먼저 판정해야
한다. 저장소 여러 개를 담은 상위 폴더에서 자동 `git init` 이 돌면 그 아래 저장소를
통째로 삼킨 저장소가 하나 생긴다. 되돌리기가 백업보다 성가시다.

현행 `notes_config._is_repository` 는 한 검사에 목적 두 개가 섞여 있다.

```python
return _config_path(root) is not None or (root / ".git").exists()
```

| 목적 | `.git` 이 대리하는가 |
|---|---|
| A. 여기가 프로젝트 루트인가 (오작동 방지) | **부정확.** git 안 쓰는 코드 저장소, 아직 `git init` 안 한 신규 프로젝트, 압축 풀어 받은 사본 |
| B. git 이 있는가 (방법론이 의존) | 정확 |

**`is_repository` 는 고치지 않는다.** 뒤집으면 `.git` 도 없고 하위 저장소도 없는 아무
폴더가 저장소가 되고, 이 판정은 초기화뿐 아니라 세션 시작 훅(`session_report`)과
검사기(`check_docs`)도 쓴다. 내려받기 폴더에서 Claude Code 를 켤 때마다 "초기화하자"고
조르게 된다 — 지금은 `.git` 부재가 그걸 막고 있다.

대신 **판정을 하나 추가한다.** `notes_config.is_workspace(root)` 는 목적 A 만 답하고,
`adopt` 의 git 정비 단계만 이것을 쓴다. 기존 동작은 그대로다.

| 신호 | `is_workspace` |
|---|---|
| 하위에 `.git` 가진 폴더가 2개 이상 | `True` → **중단** |
| 하위 폴더들이 각자 매니페스트를 가짐 | `True` → **중단** |
| 그 외 전부 | `False` → 진행 |

기록물 저장소에는 매니페스트(`pyproject.toml`·`package.json` 등)가 없다. 그래서 "매니페스트가
있어야 루트"라는 양성 판정은 쓰지 않는다 — 문서만 있는 정당한 저장소가 전부 거부된다.
매니페스트는 **워크스페이스를 반증하는 신호로만** 쓴다.

아무 폴더에서 `git init` 이 도는 것은 이미 있는 `--confirm <폴더명>` 이 막는다. 사람이
폴더 이름을 대야 실행되므로, `is_workspace` 는 사람이 이름을 잘못 댔을 때의 2차
방어다.

## 3단계 plan

읽기 전용. 파일을 하나도 움직이지 않는다. `.claude/girok-adopt.json` 을 쓴다.

| role | 규칙 | 이동 |
|---|---|---|
| `rules` | `CLAUDE.md` `AGENTS.md` `GEMINI.md` | **제자리 고정.** 도구가 루트에서 읽는다 |
| `foreign` | `docs/superpowers/**` 등 남의 도구 소유 | **제자리.** 옮기면 그쪽이 깨진다 |
| `board` | `girok.json` 의 board, 또는 `PROGRESS`·`STATE`·`현황` 이름 | 진행기록 폴더의 `PROGRESS.md` |
| `adr` | `decisionsDir` 안 + `ADR-\d+-` 또는 `\d{3}-` 이름 | 진행기록 폴더의 `docs/decisions/` |
| `doc` | 나머지 마크다운 | 진행기록 폴더의 `docs/` |
| `skip` | 비-마크다운, 코드·데이터 | 손대지 않는다 |
| `?` | **위 어디에도 확실히 안 걸림** | **`apply` 거부.** 판단 전엔 안 움직인다 |

규칙은 확실히 아는 것만 채우고 애매하면 비운다. `?` 는 모델이 내용을 읽고 채운다 —
목적지뿐 아니라 **병합 여부까지** 판단한다.

`eq-agent-v3` 에 돌렸을 때의 예상 결과는 다음과 같다.

| 파일 | role | 목적지 |
|---|---|---|
| `STATE.md` | `board` | `PROGRESS.md` |
| `CLAUDE.md` `AGENTS.md` `GEMINI.md` | `rules` | 제자리 |
| `decisions/001~006-*.md` | `adr` | `docs/decisions/ADR-001-*.md` |
| `docs/design/2026-08-31-*.md` | `doc` | `docs/` |
| `docs/superpowers/**` (4개) | `foreign` | 제자리 |
| `experiments/*.jsonl` 등 | `skip` | 손 안 댐 |
| `THESIS.md` | `?` | 모델 판단 |
| `decisions/README.md` | `?` | 모델 판단 |
| `docs/relay-responder-*.md` (2개) | `?` | 모델 판단 |

문서 약 24개 중 규칙이 20개를 처리하고 `?` 4개만 판단으로 남는다.

## 4단계 apply

### 사전조건

| 상태 | 처리 |
|---|---|
| 병합·리베이스 진행 중 (`UU`) | **중단.** 우회 없음 |
| 추적 파일에 미커밋 변경 (` M` `M `) | **중단.** 백업 태그가 못 담는다 |
| **이식 대상인** untracked (`??`) | **중단.** 파일명을 찍어 커밋을 요구 |
| 이식 대상 밖 untracked | 통과, 경고 한 줄 |
| 미push (`[ahead N]`) | 통과, 알림만 |
| `role: "?"` 가 하나라도 남음 | **중단** |
| 백업 미완 또는 검증 실패 | **중단** |

"깨끗함"의 기준은 `git status` 가 비어 있는 것이 아니라 **이식 대상 파일이 전부
커밋된 상태**다. 무관한 잡파일로 막히지 않으면서, 백업 태그가 못 담는 건 안 움직인다.

`--confirm <저장소 폴더명>` 은 `notes_init.py` 와 같은 안전장치다.

### 이동과 파일명

전부 `git mv` 로 옮긴다. `cp` 뒤 `rm` 은 금지다 — 이력이 파일을 따라가야 한다.

- ADR → `adrStyle` 에 맞춰 `ADR-001-inherited-from-v2.md`
- 일반 → 소문자 kebab-case, 공백·언더스코어는 하이픈, `YYYY-MM-DD-` 접두 보존
- **한글 파일명은 그대로 둔다.** 억지 로마자화는 이름이 뜻을 잃는다

### 병합은 이어붙이기만

두 문서를 합칠 때 **원문을 요약하거나 재작성하지 않는다.** 통째로 이어붙이고 출처를
박는다.

```markdown
## 로컬 실행 경로

<!-- girok:adopt 2026-09-01 · 출처 STATE.md -->
## 지금 상태
...
```

재작성 병합을 배제한 이유: 모델이 문장 하나를 흘려도 **검증할 방법이 없다.**
이어붙이기는 `verify` 가 *"원본의 모든 줄이 결과 문서에 그대로 있는가"* 를 기계로
검사할 수 있다. 다듬는 건 안전해진 다음 세션에 사람이 한다.

### 링크 재작성

매핑 전체를 알고 있으므로 남은 모든 `.md` 의 상대 링크를 갱신한다.

- 대상은 `[텍스트](경로)`, `![](경로)`, `[텍스트]: 경로` 세 형태
- `#앵커` 는 보존한다
- **코드블록 안은 건드리지 않는다**
- `plan` 이 "링크 N개가 바뀐다"를 미리 보여준다

### notesDir 는 기본값 유지

전면 표준화 대상이지만 **파장이 유독 크다** — 모든 문서 경로가 바뀌어 링크 재작성량의
대부분이 여기서 나온다. 그리고 `notesDir: "."` 는 girok 이 허용하는 정식 값이라
안 바꿔도 표준 위반이 아니다. **제안 항목으로 올리되 기본값은 현행 유지**, 사람이
명시적으로 켜야 움직인다.

## 5단계 verify

1. `plan` 에 있던 파일이 전부 새 자리에 있는가
2. 내용 **SHA-1** 이 같은가
3. 병합된 원문의 **모든 줄**이 결과 문서에 있는가
4. 상대 링크 중 깨진 것이 있는가
5. 백업본과 저장소의 문서 개수가 맞는가

하나라도 어긋나면 복원 명령을 그대로 출력한다.

```
git checkout girok-adopt-before-20260901 -- .
# 또는 백업 폴더에서 통째로 되돌린다
```

## 매핑 파일

`.claude/girok-adopt.json` 에 남기고 **커밋한다.** 무엇이 어디로 갔는지가 곧
추적표이고, 나중에 "그 문서 어디 갔지?"에 답한다.

```json
{
  "generated": "2026-09-01",
  "gitSetup": { "init": true, "gitignoreAdded": ["__pycache__/"], "secrets": [], "large": [] },
  "backup": { "path": "eq-agent-v3-girok-backup-20260901", "files": 783, "bytes": 4823552 },
  "files": [
    { "from": "STATE.md", "to": "PROGRESS.md", "role": "board",
      "merge": null, "sha1": "…", "bytes": 4907, "why": "girok.json board" }
  ]
}
```

## notes 통합 지점

| `/notes` 단계 | adopt |
|---|---|
| 2절 초기화 (스냅샷 없음) | `backup` → git 정비 → survey → `notes_init` → `plan`·`apply`·`verify` |
| 4절 점검 (정상) | `plan` 을 돌려 **"이식 안 된 문서 N개"** 를 점검 결과에 함께 보고 |

4절 추가가 필요한 이유: `eq-agent-v3` 는 이미 girok 이 들어가 있어 지금 `/notes` 를
치면 "정상"만 나온다. 정리 안 된 문서가 있어도 아무도 말해주지 않는다.

## 중단점

자동화가 원칙이다. 나머지는 전부 "해결하고 기록하고 진행"한다. 멈추는 곳은 셋뿐이다.

1. **워크스페이스 오판.** 해결이 불가능하다 — 저장소 여러 개를 하나로 뭉개는 건
   고칠 수 있는 실수가 아니다.
2. **백업 실패.** 안전망 없이 파일을 건드리지 않는다.
3. **사전조건 위반.** 병합 진행 중이거나, 대상 파일이 미커밋이거나, `role: "?"` 가
   남아 있는 경우.

## 테스트

`tests/` 에 픽스처 저장소를 만들어 TDD 로 간다. 최소한 다음을 덮는다.

- git 없는 폴더 → `git init` 되고 첫 커밋이 생긴다
- 하위 `.git` 이 2개인 폴더 → **중단한다**
- 매니페스트 없는 문서 폴더 → **진행한다** (판정 뒤집기의 회귀 방지)
- 백업 후 파일 개수와 바이트가 일치한다
- `role: "?"` 잔존 시 `apply` 가 거부한다
- 이동 후 SHA-1 이 전부 보존된다
- 병합 후 원본의 모든 줄이 결과에 있다
- 링크가 새 경로로 재작성되고, 코드블록 안 경로는 안 바뀐다
- 미커밋 변경이 있는 대상 파일이 있으면 `apply` 가 거부한다

## 별도 안건

이번 범위 밖이지만 기록해 둔다.

**`git push` 는 자동이 아니다.** 훅은 push 를 실행하지 않는다. `gate_rules.py` 가
force push 를 차단하고 `doc_followup.py` 가 결과를 보고할 뿐이며, "커밋 즉시 push" 는
`project-notes` 스킬의 행동 규칙이라 실행 주체는 에이전트다. 자동처럼 보이는 이유는
`templates/settings.json` 이 `Bash(git push:*)` 를 allowlist 해 승인창이 안 뜨기
때문이다. 승인이 생략된 것이지 실행이 자동인 게 아니다. 이 구분을 사용자 문서에
명시할지는 별도로 정한다.
