## 먼저 알아둘 것: 저장소는 폴더로 정해진다

**Claude Code 에는 "어느 저장소에서 작업할까요?" 선택 화면이 없다.** 켠 폴더가 곧 작업
대상이다. 그래서 순서가 항상 이렇다:

```
저장소 폴더로 이동  →  거기서 claude 실행
```

```bash
cd <저장소 폴더>
claude
```

폴더를 잘못 잡고 켜면 그 폴더 기준으로 일하게 된다. 세션 첫 줄에 현황판 경로가 찍히므로
(§4) 거기서 확인하면 된다.

여러 저장소를 오갈 거면 각각 별도 터미널에서 켜는 게 낫다 — 한 세션 안에서 폴더를 옮겨
다니면 규칙이 어느 저장소 것인지 흐려진다.

## 1. 머신당 1회 설치

새 PC 를 쓰거나 처음 합류할 때만 한다. 이미 한 적 있으면 §3 으로.

### 1-1. 있어야 하는 것

| | 확인 |
|---|---|
| Python 3.10 이상 | `python --version` |
| git | `git --version` |
| 원격 저장소 접근 권한 | 각자 계정 설정 |

> [!WARNING]
> Windows 에서 `python3 --version` 이 아무것도 안 하고 끝나면 그건 Microsoft Store
> 바로가기지 Python 이 아니다. `python --version` 으로 확인하고, 안 나오면
> [python.org](https://www.python.org/downloads/) 에서 설치할 것.
>
> Git Bash 는 필요 없다 — 훅 진입점이 bash·cmd.exe·PowerShell 셋 다에서 돈다.

### 1-2. 저장소 받고 켜기

```bash
git clone <저장소 주소>
cd <저장소 폴더>
claude
```

처음 켜면 **"이 폴더를 신뢰하겠느냐"** 고 묻는다. **예** 를 눌러야 한다. 신뢰하기 전에는
저장소에 커밋된 설정이 무시돼서 플러그인이 오지 않는다.

### 1-3. 플러그인 설치 — 도입·갱신을 할 사람만

> [!TIP]
> **이미 girok 이 들어간 저장소에서 작업만 할 거라면 건너뛴다.** 훅·검사기·규칙 전문이
> 저장소에 함께 커밋돼 있고, 훅 등록도 저장소의 `.claude/settings.json` 에 있다.
> §1-1 (Python·git) 과 §1-2 (폴더 신뢰) 만 하면 같은 검사가 그대로 돈다.

플러그인이 필요한 것은 **저장소를 새로 도입할 때(§2)와 규칙 개정을 내려받을 때(§7)** 다.
터미널에서 (Claude 밖에서) 한 번:

```bash
claude plugin install girok@mongdang
```

설치 후 **Claude 를 껐다 다시 켠다.**

### 1-4. 확인

다시 켠 세션에서 이렇게 물어본다:

```
지금 이 저장소 현황 알려줘
```

§4 같은 내용이 나오면 된 것이다. 아무것도 모르는 것처럼 답하면 §7 로.

## 2. 저장소에 처음 도입할 때

아직 이 방법론을 안 쓰는 저장소에 넣는 경우다. 저장소당 한 번만 한다.

저장소 폴더에서 Claude 를 켜고:

```
/notes
```

무엇을 만들지 물어본다 — 진행기록 폴더 이름, 안전 게이트 사용 여부(실장비를 제어하는
프로젝트면 켠다), 병행 작업 여부. 답하면 나머지는 알아서 만든다.

만들어지는 것:

```
<저장소>/
├── .claude/
│   ├── settings.json          훅 등록 + 플러그인 선언 — 커밋함
│   └── girok.json             이 저장소 설정(작업자 목록 등) — 커밋함
└── <진행기록폴더>/
    ├── CLAUDE.md              지침 + 작업 전 필수 확인 블록
    ├── GEMINI.md · AGENTS.md  다른 AI 에이전트용 포인터
    ├── .method/               규칙 전문 사본 — 사람이 손대지 않는다
    └── docs/
        ├── PROGRESS.md        현황판
        ├── SAFETY_GATE.md     안전 게이트 (켰을 때만)
        ├── decisions/         결정 기록(ADR)
        └── archive/           완결된 서사
```

만든 뒤 **커밋한다.** 특히 `.claude/settings.json` 이 커밋돼야 팀원이 이 저장소를 clone
했을 때 **훅이 걸린다** — 훅 등록이 그 파일에 들어 있다.

> [!NOTE]
> 팀원은 플러그인을 설치하지 않아도 된다. 폴더를 신뢰하고 Python 이 있으면 같은 검사가
> 돈다. 플러그인이 필요한 것은 규칙 개정을 내려받을 사람(§7)뿐이다.

### `workers` 는 채워야 진행된다

`.claude/girok.json` 의 `workers` 에 사람과 git 이메일을 적어두면, 세션마다 누구인지
묻지 않고 자동으로 알아본다.

```json
"workers": { "abc": "abc@example.com", "xyz": "xyz@example.com" }
```

> [!IMPORTANT]
> 병행 모드에서 내 `git user.email` 이 여기에 없으면, 세션이 누구인지 묻고 **답이 이 파일에
> 기록되기 전까지 문서 쓰기·커밋·push 가 차단된다.** 잘못된 id 로 기록되면 병합할 때 남의
> 기록에 섞이고, 나중에 되돌리기 어렵기 때문이다.
>
> 막히지 않는 것: **코드 편집**(기록이 아니다) · **이 설정 파일 자체**(답을 적어야 하니까) ·
> **`SAFETY_GATE.md`**(안전 정보는 기다리지 않는다).
>
> 혼자 쓰는 저장소라면 `parallelMode: false` 로 두면 된다 — 이 절차 전체가 꺼진다.

## 2-1. 이미 문서 체계가 있는 저장소라면

기본값으로 뼈대를 만들면 진짜 문서 옆에 빈 문서 한 벌이 더 생긴다. 그래서 `/notes` 는
초기화 전에 **먼저 저장소를 읽는다.** 직접 돌려볼 수도 있다:

```bash
python <플러그인>/scripts/notes_survey.py
```

읽기 전용이고, 결과는 **제안**이다. 예시:

```
저장소: eq-agent · 문서 75건

제안하는 설정:
  진행기록 위치  .
  현황판        STATE.md
  결정 기록      decisions (numbered)
  안전 게이트    켬
  아카이브       끔
  병행 작업      끔

살펴볼 것 4건:
  - 코드에 인터락·모션 관련 표현이 있다 — 실장비를 제어하면 안전 모듈을 켜는 쪽을 권한다
  - `CLAUDE.md` 가 아카이브 폴더를 만들지 않는다고 못 박아 뒀다 — 그 관례를 따른다
  - `METHOD.md` 크기가 20,090바이트로 기준을 넘는다 — 아카이브로 옮길 때다
  - 커밋 이메일이 4개다 — 사람이 여럿이면 병행 작업을 켜고 workers 를 채울 것
```

| 추론하는 것 | 어떻게 |
|---|---|
| 진행기록 위치 | `docs/` 와 자기 규칙 파일을 함께 가진 폴더, 없으면 저장소 루트 |
| 현황판 | 이름과 절 구성. **후보가 둘 이상이면 고른 것과 나머지를 함께 알려준다** |
| 결정 기록·형식 | `decisions`·`adr` 폴더의 파일명에서 판별 |
| 안전 게이트 | 게이트 문서 · 코드의 안전 마커 · 인터락·모션 표현 |
| 아카이브 | 기존 폴더. **"아카이브 폴더를 만들지 않는다"고 적힌 저장소는 그 관례를 따른다** |
| 병행 작업 | `docs_<id>/` 폴더 (커밋 이메일 수로 정하지 않는다 — 한 사람이 여러 머신을 쓴다) |

> [!IMPORTANT]
> 이건 **제안이고 아무것도 쓰지 않는다.** 특히 "현황판 후보가 여럿" 같은 항목은 사람만
> 답할 수 있다. 틀린 것이 있으면 그대로 말하면 된다.

이미 도입한 저장소에서 다시 돌리면, 설정과 지금 저장소 모습이 어긋난 곳을 알려준다 —
도입 시점의 판단(특히 안전 모듈)이 아직 맞는지 점검하는 용도다.

## 3. 평상시 — 매일 하는 것

```bash
cd <저장소 폴더>
claude
```

**끝이다.** 칠 명령은 없다. 세션이 시작하면서 알아서 확인한다 — 규칙 판본, 내가 누구인지,
현황판 상태, 안전 게이트 열린 항목. 그 다음엔 그냥 하려던 일을 말하면 된다.

세션을 마칠 때도 따로 할 게 없다. 커밋 안 한 것·push 안 한 것·현황판에 오늘 기록이 없는
것이 있으면 알려준다.

## 4. 세션 첫 화면에 뭐가 뜨나

실제로 들어가는 내용은 이렇다:

```
[girok] ready vX.Y.Z
작업자 abc (git user.email 로 확정)
현황판 notes/docs_abc/PROGRESS.md — 활성 위험 0건, 열린 질문 0건
안전 게이트 OPEN 1건
안전: 게이트 OPEN 항목이 남아 있는 동안 실장비 모션 명령을 실행하거나 안내하지 않는다 ...
```

줄별로:

| 줄 | 뜻 |
|---|---|
| `ready vX.Y.Z` | 이 저장소의 규칙이 적용 중이라는 표시. **이게 없으면 검사가 돌지 않는 상태다** |
| `작업자 abc` | git 이메일로 자동 판별한 결과. 따로 묻지 않고 확정됐다는 뜻 |
| `현황판 ...` | 어느 문서를 읽었는지 + 지금 열려 있는 위험·질문 개수 |
| `안전 게이트 OPEN n건` | 실장비 모션 전에 닫아야 할 항목 수 |

> [!IMPORTANT]
> 이 내용은 **Claude 에게 전달되는 것**이지 터미널에 항상 그대로 찍히는 게 아니다.
> 눈으로 확인하고 싶으면 `지금 상태 알려줘` 또는 `/notes` 라고 하면 된다.

**여기서 어느 저장소인지도 알 수 있다** — 현황판 경로가 그 저장소 기준으로 찍히므로,
엉뚱한 폴더에서 켰으면 경로가 이상하거나 "현황판을 찾지 못했다" 가 나온다.

## 5. 알아서 되는 것 / 물어보는 것

### 알아서 되는 것

- 문서를 고치면 검사기가 돌아 깨진 목차·표를 바로 알려준다
- 병행 작업 문서의 `최종 수정` 스탬프가 시계 기준으로 갱신된다
- 세션 마무리에 미push 커밋·오늘 기록 누락을 알려준다
- 실장비 모션 얘기를 꺼내면 그 자리에서 열린 게이트 항목을 상기시킨다

### 물어보는 것

| 상황 | 왜 묻나 |
|---|---|
| git 이메일이 `workers` 에 없을 때 | 잘못된 id 로 기록되면 병합 때 남의 기록에 섞인다 |
| 상대 작업자의 새 내용이 들어와 있을 때 | 병합은 승인 없이 하지 않는다 |
| 저장소를 처음 초기화할 때 | 무엇을 만들지 정해야 한다 |

## 6. 막혔을 때

차단되면 이유와 해소 방법이 같이 나온다. 자주 보게 될 것들:

| 차단 메시지 | 왜 | 어떻게 |
|---|---|---|
| 게이트 OPEN 항목이 남아 있어 모션 명령을 실행하지 않는다 | 실장비 안전 | 담당자가 `SAFETY_GATE.md` 항목을 확인하고 닫은 뒤 다시 |
| 확인자 칸은 에이전트가 채우지 않는다 | 실장비 검증을 AI 가 대신할 수 없다 | 사람이 실명으로 직접 적는다 |
| `SAFETY-STUB` 마커가 추가됐는데 게이트 변경이 없다 | 등재 안 된 안전 우회가 커밋되는 것을 막는다 | 게이트 표에 항목을 추가하고 같은 커밋에 넣는다 |
| `.method/` 는 직접 고치지 않는다 | 손으로 고치면 사본이 다시 갈라진다 | 규칙 개정은 플러그인 저장소에서, 그다음 `/notes` |
| 작업자가 확정되지 않았다 | 잘못된 id 로 기록되면 병합 때 섞인다 | `workers` 에 내 이메일을 한 줄 추가 |
| force push 금지 | 변경 이력이 곧 결정 기록이다 | 되돌릴 게 있으면 `git revert`. 정말 해야 하면 `GIROK_FORCE_PUSH_REASON` 에 이유(8자 이상)를 담아 실행 — 그 이유가 기록에 남는다 |
| 참고 저장소에 push 금지 | 대조·이식 출처로만 쓰는 저장소다 | 작업 저장소에 반영하고 ADR·게이트로 기록 |

**이건 규칙이지 버그가 아니다.** 우회하지 말고 위 방법대로 푼다.

## 7. 문제 해결

### `ready` 표시가 없다 / 규칙을 모르는 것 같다

순서대로 확인한다.

```bash
# 1. 폴더를 신뢰했나 — Claude 를 켜서 신뢰 프롬프트가 다시 뜨면 예를 누른다
#    신뢰하기 전에는 저장소에 커밋된 훅 등록이 무시된다

# 2. Python 이 있나
python --version
```

그래도 안 되면 Claude 를 완전히 껐다 켠다. 훅은 세션 시작 때만 붙는다.

### "스냅샷 v0.6.2 ≠ 플러그인 v0.7.0" 이 뜬다

규칙이 갱신됐는데 이 저장소의 사본이 낡았다는 뜻이다.

```
/notes
```

라고 하면 맞춰준다. 맞춘 결과는 커밋한다.

### 규칙을 고쳤는데 반영이 안 된다

플러그인 캐시는 자동으로 갱신되지 않는다.

```bash
claude plugin marketplace update mongdang
claude plugin update girok@mongdang
```

그리고 Claude 를 다시 켠다.

> [!WARNING]
> 규칙을 고친 사람에게: **플러그인 저장소의 `plugin.json` 버전을 올려야 한다.** 설치본은
> 버전별 폴더에 저장돼서, 버전을 그대로 두면 이미 설치한 사람은 계속 옛 사본을 쓴다.

### 플러그인이 없는 PC 에서 작업해야 한다

그대로 작업하면 된다. 훅·검사기·규칙 전문이 저장소에 함께 커밋돼 있고, 훅 등록도
저장소의 `.claude/settings.json` 에 있다 — 폴더를 신뢰하고 Python 이 있으면 세션 시작
블록도 뜨고 차단도 걸린다.

`ready` 가 안 뜨면 저장소의 스냅샷이 이 방식 이전 판본이라는 뜻이다. 플러그인이 있는
PC 에서 `/notes` 를 한 번 돌려 등록을 만들고 커밋하면 된다.

### 플러그인도 Claude Code 도 못 쓰는 도구로 작업해야 한다

`<진행기록폴더>/.method/RULES.md` 에 규칙 전문이 그대로 있다. 그 파일을 끝까지 읽히고
작업하면 된다. Gemini CLI·Codex 용 포인터(`GEMINI.md`·`AGENTS.md`)도 그 파일을 가리킨다.

### 검사기만 따로 돌리고 싶다

```bash
python <진행기록폴더>/.method/scripts/check_docs.py
python <진행기록폴더>/.method/scripts/marker_scan.py
python <진행기록폴더>/.method/scripts/method_sync.py verify
```

플러그인이 없어도 돈다 — 저장소에 같이 커밋돼 있기 때문이다.
